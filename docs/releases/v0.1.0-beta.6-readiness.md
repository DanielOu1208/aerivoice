# beta.6 release readiness

Candidate: `v0.1.0-beta.6`, marketing version `0.1.0`, build `2026091202`.

## Scope

The release includes earlier Soniox connection setup, bounded Meta catch-up,
verified clipboard restoration, launch preparation, and optional local diagnostics.
Provider defaults and the sound-cue default remain unchanged.

New local evaluation harness code, transport adapters used only by that harness,
lifecycle observation hooks, fixture audio, run reports, credentials, and Keychain
administration helpers are excluded. Existing production diagnostics and their
regression tests remain part of the app source.

## Review

- Strict review covered capture and coordinator lifecycle, provider pacing,
  diagnostics storage and privacy, clipboard restoration, and release packaging.
- Fixed a retention regression: disabled startup previously discarded only its
  recovery checkpoint, allowing expired completed history to survive later launches.
- Updated privacy documentation to describe verified clipboard restoration and
  the current diagnostics retention limit.
- Decomposed the 1,235-line coordinator test file into functional tests and
  scoped test support. Tests use controlled doubles and do not call live providers.

## Verification status

- Normal full suite: 319 passed, three opt-in live tests skipped, zero failures.
- Focused diagnostics retention tests: 24 passed, including three new regressions.
- Release static analysis and unsigned arm64 build passed.
- Working-tree secret scan and whitespace checks passed.
- Fresh-clone distribution checks, CI, signing, notarization, and artifact
  verification are pending for this exact release candidate.

## Manual checks remaining

Fresh-user quarantined installation/onboarding, beta.5 credential/settings upgrade,
microphone-to-provider-to-paste dictation, launch at login, default cleanup route,
and 96/48 kHz audio-route transitions have not been repeated for this artifact.
TextEdit and Discord/Electron insertion also require current-artifact acceptance.
Automated cancellation and clipboard tests do not establish full real-app coverage.

The GitHub release is prepared as a draft. Publishing and pushing the release tag
remain separate steps under `docs/RELEASING.md`.
